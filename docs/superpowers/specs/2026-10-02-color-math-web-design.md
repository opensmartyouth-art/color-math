# Color Math 웹 — 설계

- 날짜: 2026-10-02
- 근거: 노션 「Color 관계」 문서 묶음, 특히 「08 · 생성기 — Primary 하나로 전체 세트 뽑기」
- 상태: 구현 범위 확정 (오너 결정 2026-10-02)

## 1. 무엇을 만드나

Primary 컬러 하나를 넣으면, 14개 디자인 시스템 실측에서 뽑은 상수로 Neutral·시맨틱 컬러와 다크모드까지 만들어 주는 웹 서비스.
신입 1인 디자이너가 Foundation의 Color를 세울 때 출발점으로 쓰는 것이 목적이다.

성공 기준

1. Primary HEX를 넣으면 8개 계열 × 10단계 컬러칩이 라이트/다크 두 벌로 나온다.
2. `#3182f6`을 넣었을 때 노션 08의 예시 출력과 채널당 ±1/255 이내로 같다.
3. 칩 하나를 골라 컬러피커로 고칠 수 있고, 고친 값이 JSON에 그대로 담긴다.
4. 다운로드한 JSON이 W3C 디자인 토큰(DTCG) 형식이라 Tokens Studio·Style Dictionary에 바로 넣을 수 있다.

### 3-1. 기본 상태
- 처음 열면 Primary는 `#3182f6`(노션 예시)로 채워져 있다.
- 6자리 HEX(`#RRGGBB`, `RRGGBB`)는 입력되는 순간 오른쪽 칩이 다시 만들어진다. 3자리 축약(`#RGB`)은 Enter를 누르거나 입력란을 벗어날 때 반영한다(`#318`은 `#3182f6`을 치는 중간이기도 해서, 바로 반영하면 고친 칩이 날아간다). 틀린 입력이면 안내 문구를 띄우고 직전 팔레트를 유지한다.
- Primary가 바뀌면 고친 칩 값과 선택 상태는 초기화된다.

### 3-2. 오른쪽 패널
- 우측 상단: 라이트/다크 전환. 다크를 고르면 오른쪽 패널 바탕도 어둡게 바뀌어 다크 칩을 제 배경 위에서 본다.
- 본문: 계열 8줄(primary, gray, red, orange, yellow, green, blue, purple) × 10칸(50~900). 각 칩에 단계와 HEX를 적고, 글자색은 칩과 대비가 큰 쪽(흰/검)을 쓴다. 칩 줄 폭이 640px보다 좁으면 HEX는 숨기고 단계만 적는다(칩을 누르면 왼쪽에서 확인). 고친 칩에는 점 표시.
- 우측 하단: `JSON 다운로드`. 화면에 보이는 값(고친 값 포함, 라이트·다크 모두)을 그대로 내려받는다.

### 3-3. 칩을 눌렀을 때
- 왼쪽 패널: Primary 입력 아래에 고른 칩의 정보가 나온다.
  - 이름(`gray-100`)과 모드(라이트/다크), 큰 견본
  - HEX · RGB · HSL · OKLCH
  - 흰 배경·검정 배경 대비비와 WCAG 판정(AAA / AA / AA 큰 글씨 / 미달)
  - 고친 칩이면 "생성값 #xxxxxx"와 `생성값으로 되돌리기`
- 오른쪽 패널: 칩 목록 대신 컬러피커가 뜬다. 피커와 HEX 입력으로 값을 바꾸면 그 칩 하나만 바뀐다(지금 보는 모드에만).
  - 열리면 HEX 입력에 포커스가 간다. HEX 입력의 3자리 축약은 Primary 입력과 같은 규칙(Enter·포커스 이탈 시 반영).
  - 생성값과 같은 값으로 되돌리면 수정 표시가 사라진다.
  - 좌측 상단 `← 컬러칩` 또는 Esc로 목록으로 돌아가고, 포커스는 방금 편집한 칩으로 돌아간다.
  - 피커 상태에서 라이트/다크를 바꾸면 같은 칩의 다른 모드 값을 편집한다.
  - OKLCH 색상각은 채도가 0에 가까운 색(무채색)에서는 `—`로 표시한다.
- 연쇄 수정(예: gray-100을 바꾸면 200·300·400도 맞춰 바뀜)은 하지 않는다. → `docs/BACKLOG.md`

## 4. 생성 공식 (노션 08 → 코드)

모든 계산은 OKLCH(sRGB, D65). L은 0~100, 단계 인덱스 i는 50=0 … 900=9.

| 상수 | 값 |
| --- | --- |
| 명도 사다리 `LADDER` | 98.5, 90.2, 81.9, 73.6, 65.3, 57.0, 48.4, 39.8, 31.2, 22.6 |
| primary 채도 아치 `PRIMARY_ARC` | 0.081, 0.252, 0.427, 0.625, 0.833, 0.932, 0.924, 0.797, 0.605, 0.407 |
| neutral 채도 아치 `NEUTRAL_ARC` | 0.030, 0.332, 0.563, 0.746, 0.874, 0.949, 0.980, 0.891, 0.766, 0.598 |
| 회색 색상각 | 263.3° |
| 회색 최대 채도(tinted) | 0.018 |
| 시맨틱 색상각 / 비틀림(°/칸) | red 26.7 / +0.90 · orange 49.3 / −4.32 · yellow 90.9 / −2.21 · green 154.7 / −0.19 · blue 259.1 / +1.44 · purple 303.1 / −0.67 |
| 다크 들어올리기 | 122.4, 범위 6~97 |

1. **앵커**: 입력의 L과 가장 가까운 사다리 칸. 가장 가까운 칸이 400 또는 600이면 500으로 스냅.
2. **primary 명도**: 앵커 칸만 입력 L로 옮기고, 50(98.5)~앵커, 앵커~900(22.6)을 각각 직선 보간.
3. **채도 예산**: `peak = C_입력 / PRIMARY_ARC[앵커]`. primary와 시맨틱의 i칸 목표 채도 = `peak × PRIMARY_ARC[i]`.
4. **색상각 비틀림**: primary는 `H(i) = H_입력 + k × (i − 앵커)`. k는 위 6개 (색상각, 비틀림) 점 사이를 원형 선형 보간.
5. **회색**: L은 기본 사다리, 채도 `0.018 × NEUTRAL_ARC[i]`, 색상각 263.3° 고정, 비틀림 없음.
6. **시맨틱**: L은 기본 사다리, 채도는 3번 예산, 색상각 `H_계열 + k_계열 × (i − 5)`.
7. **색역**: sRGB 밖이면 L·H를 지키고 채도만 이분 탐색으로 줄인다.
8. **앵커 칸**: 라이트 primary의 앵커 칸은 입력 HEX를 그대로 쓴다.
9. **다크**: 라이트 결과 HEX를 OKLCH로 읽어 `L_dark = clamp(122.4 − L, 6, 97)`, C·H는 그대로, 다시 색역 클리핑.

노션 08에 적혀 있지 않아서 예시 출력으로 역산해 정한 부분: 1의 스냅 규칙, 3의 `peak` 정규화, 5·6에서 기본 사다리를 쓰는 점, 9에서 라이트 결과 HEX를 출발점으로 쓰는 점.
노션의 상수가 소수 셋째 자리로 반올림되어 있어 예시와 완전히 같지는 않고, 채널당 최대 1/255 차이가 난다.

## 5. JSON (W3C 디자인 토큰)

```json
{
  "$description": "Color Math · primary #3182f6 · anchor 500",
  "light": {
    "primary": {
      "50": { "$type": "color", "$value": "#f6fbff" },
      "…": "…"
    },
    "gray": { "…": "…" }
  },
  "dark": { "…": "…" }
}
```

- 계열 이름: `primary gray red orange yellow green blue purple`, 단계 이름: `50 100 … 900`.
- `$value`는 소문자 `#rrggbb`. 도구 호환성이 가장 넓은 문자열 형식을 쓴다.
- 파일 이름: `color-math-3182f6.json`.

## 6. 구조

| 파일 | 하는 일 |
| --- | --- |
| `src/color/convert.ts` | HEX 파싱, HEX↔OKLCH, HSL, 상대휘도·대비비·WCAG 판정, 색역 클리핑 |
| `src/color/generate.ts` | 4장의 공식으로 팔레트 생성 |
| `src/color/tokens.ts` | 팔레트 → DTCG JSON |
| `src/App.tsx` | 상태(입력, 모드, 선택, 고친 값)와 두 패널 배치 |
| `src/components/ChipGrid.tsx` | 칩 목록 |
| `src/components/ColorInfo.tsx` | 왼쪽 색 정보 |
| `src/components/ChipEditor.tsx` | 오른쪽 컬러피커 |

상태는 App 한 곳에만 둔다: `input`, `mode`, `selected {family, step} | null`, `overrides { light: {}, dark: {} }`.
화면에 보이는 값 = 생성값 위에 overrides를 덮은 것. JSON도 이 값을 쓴다.

## 7. 테스트

- `convert`: `#3182f6` → OKLCH(62.01, 0.1906, 258.2°), HSL(215.3°, 91.6%, 57.8%). Toss grey 500/600/700 흰 배경 대비 3.04 / 4.62 / 7.11. 클리핑 결과는 sRGB 안이고 L·H 유지.
- `generate`: `#3182f6` → 앵커 500, 비틀림 +1.43°/칸, 라이트 primary·gray·red·green·yellow와 다크 primary·gray 70칸이 노션 예시와 채널당 ±1 이내. gray 흰 배경 대비 50:1.04 … 900:17.08. 다른 입력(`#ff6600`, `#06c755`, `#000000`, `#ffffff`)도 모든 칸이 올바른 HEX이고 라이트 명도가 단조 감소.
- `tokens`: DTCG 구조, 계열 8 × 단계 10 × 모드 2.
- `App`: 칩 80개 렌더, 입력 변경 시 primary-500 갱신, 틀린 입력 안내, 모드 전환, 칩 클릭 → 정보·피커 표시, HEX 수정 → 칩 반영과 되돌리기, 다운로드 실행.
